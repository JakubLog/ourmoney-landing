## Konwencje kluczy

| Zasada | Przykład |
|--------|---------|
| Namespace = PascalCase | `HomePage`, `BlogPage` |
| Klucze = camelCase | `learnMore`, `heroHeadline` |
| Zagnieżdżenie max 3 poziomy | `HomePage.hero.cta` |
| Meta zawsze w obiekcie `meta` | `HomePage.meta.title` |
| Liczba mnoga — ICU format | `"{count, plural, one {# post} other {# posty}}"` |
| Daty — ICU format | `"Opublikowano {date}"` (formatowanie przez next-intl) |

## Sanity + i18n

Treści z Sanity (blog, FAQ) mają własne pole `language` (`pl` / `en`).
Filtrowanie w GROQ z language fallback: `*[_type == "blogPost" && (language == $language || (!(defined(language)) && $language == "pl"))]`

Jeśli EN wersja posta nie istnieje → fallback na PL (zdefiniuj w komponencie):
```typescript
const post = await client.fetch(POST_QUERY, { slug, locale })
  ?? await client.fetch(POST_QUERY, { slug, locale: 'pl' });
```

Ta sama zasada dotyczy każdej encji CMS, która ma pole `language`. Autorzy: dokument per język
z **tym samym slugiem** (`/pl/autor/x` ↔ `/en/author/x`), spięte `translation.metadata`;
`AUTHOR_QUERY` bierze wersję w języku strony (`order(select(language == $language => 0, 1))`),
a gdy jej nie ma - dowolną. `o-nas/page.tsx` dodatkowo dociąga PL, gdy lista dla locale jest pusta
(do 2026-09-13 `/en/about` miało pustą sekcję zespołu). Posty EN wskazują dokument autora EN.

Kategorie bloga są tłumaczone jak posty (`translation.metadata`, własny slug per język) -
patrz ADR-013 w INDEX.md.
